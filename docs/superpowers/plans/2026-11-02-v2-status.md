## 7. Gotchas that cost time

- **Supabase OAuth return address:** a bare-IP host is rejected and falls back to the site URL; Supabase also rewrites `hissa://` to `hissa:?code=...`. Everything is in [decision 0004](../../decisions/0004-google-sign-in-return-address.md). Expo Go also uses PKCE `plain`.
- **Gemini timeouts:** the old model had a 15 to 72 s latency tail; the free tier has a per-minute quota. See [decision 0005](../../decisions/0005-gemini-timeouts-retries-and-model.md). A `GEMINI_MODEL` line in `.env` overrides the code default.
- **Expo on the user's Mac:** `httpd` and `nginx` hold ports 8081 and 8082; Expo rewrites `frontend/tsconfig.json` on every start (discard it with `git checkout -- frontend/tsconfig.json` before merging); `EXPO_PUBLIC_*` values are read at start, so restart after editing `.env`; `EXPO_PUBLIC_API_URL` must be the computer's LAN address for any phone.
- **Direct database writes are closed on purpose** ([decision 0006](../../decisions/0006-v2-learning-loop-and-backend-only-writes.md)). The app must call the API for meals, check-ins and friend, goal and notification data.
- **The Supabase MCP and the Supabase CLI can be logged into different accounts.** The CLI sees the Hissa project; check which account the MCP sees (`list_projects`) before relying on it.
- **Session logs:** hooks append to `.claude-logs/`, which leaves modified tracked files in the main checkout; they can block a fast-forward merge. A pushed log once contained a stale one-time OAuth code (no keys).
- **Opt-in database tests** share tables and can flake in parallel.

## 8. Working agreements that held up

- One task per implementer, each in its own git worktree (`.worktrees/<name>` inside a checkout, or a sibling directory); independent reviewer; fix rounds; scoped re-review; then merge. Every agent is told to use Superpowers (test-driven development, verification before completion), Ponytail (smallest working change) and Graphify (`graphify update .` rebuilds the code graph; it is git-ignored, copy it into new worktrees).
- No deploy, no remote migration, no external posting, no force-push unless the user explicitly says so. Never commit `.env`, keys or the Google client secret (kept outside the repo in `~/.config/hissa/`).
- Report what was not verified; never describe a simulated check as a real one.
