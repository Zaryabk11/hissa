## v2 outline: Duo Streaks

1. `buddy_pairs` flow in `streaks`: create invite code (6 chars `A-Z0-9`), accept code (service role, checks one open pair per person), end pair.
2. `meals.saveMeal` calls `streaks` through its `index.ts` to write a `streak_days` row for the PKT day (idempotent). v1 left this hook out on purpose: `saveMeal` does not call `streaks` yet, so this is the first thing to build. `streaks` is still a 501 stub.
   - v1 already creates a `profiles` row at sign-up (trigger, with backfill), so `buddy_pairs` and `streak_days` can reference every user without extra setup.
3. Streak rule: a day counts when a person saved at least one meal; the shared streak grows only when both count; it resets at midnight PKT if either misses.
4. One nudge per buddy per day.
5. Buddy read endpoint returns only `{ loggedToday: boolean, streak: number }`. Test that meals, photos and calories never appear in any buddy response.

## v3 outline: Food and Feel, learning, recipes

1. v3a Feel: `feel_checkins` (table exists), due 90 min after a saved meal, weekly pattern rule (one answer in 60% or more of a category's check-ins, at least 3 check-ins), Gemini rewrites only the flagged pattern into one sentence; copy says "pattern", never "cause".
2. v3b Learning: migration for `user_avoids` and `dishes.protein_type` (spec section 7); onboarding avoid-list endpoints in `profiles`; hard filters applied in code.
3. v3c Recipes (stretch): needs an open recipe set with ingredients and steps first (spec section 9); `recipes` and `recipe_feedback` tables; deterministic ranking; one-tap "not for me".
